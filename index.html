Introduction
The motivation · a case

Good policy can still cause harm

A minimum-wage case

A regional government raised the minimum wage so low-paid workers could earn more — but some small businesses could not absorb the cost, so they let workers go.

The low-wage employees the policy was meant to help ended up not earning more — they lost their jobs instead.

So before a government launches a policy, no one can know what effects and problems it will bring. Sometimes a policy meant to do people good ends up harming them. To reduce that risk, governments can run a policy simulation before launching it.

Neumark et al. (2014)
Introduction
The mechanism

Simulation: policy → decision → outcome

A policy changes a person's circumstances, which shapes their decision, which guides their behaviour; behaviours interact to produce a social phenomenon we can observe.

The decision step in the middle is the weak link.

Introduction
The traditional approach

One fare rise, one fixed rule

The traditional approach is, in essence, a fixed set of rules: every 10% fare rise cuts passengers within 10 km by 5%, beyond 10 km by 2%. But if your fare went up, would you still ride? It depends on a bike, the rain, even how lazy or afraid of driving you are — something a fixed rule cannot capture.

Ghaffarzadegan et al. (2024); Jamali & Lazarova-Molnar (2026)

The AI approach

AI models each person

An agent stores and combines a person's memory, background, and personality — so it can think and decide like an independent person. But its brain, the LLM, can never be 100% accurate.

The catch

How the LLM predicts — it does not know

At each step the LLM picks the token with the highest probability — but the most likely answer is not always the correct one.

A guess, not a fact

Tom can sit on Jerry. An LLM only outputs the most likely result — but as situations differ, it will inevitably make mistakes.

Introduction
The consequence

A small guess grows down the chain

A small error at the decision step is amplified again and again, until the social outcome deviates completely.

The evaluation
The fix

An evaluation system for the decision step

No one has checked whether the decisions AI agents produce match how real people behave. So this essay argues for an evaluation system built specifically for that decision step — and to picture how it works, think of it like an exam.

Two aims
1Verify whether the decision simulation is accurate.
2Where it is not, pinpoint the root cause and iterate until it meets the standard.
The exam analogy

To judge whether an agent's decision is correct, we run it like an exam: the benchmark is the questions (real past behaviour), the rubric is the grading criteria, and a domain expert + LLM mark it together. If a score falls short, the result is fed back to the agent so it improves — looping until it passes the threshold and can "graduate" to deployment or be used as evidence.

[ FIGURE ] The evaluation loop: Decision Agent → Benchmark (exam questions) → Rubric (marking criteria) → Expert + LLM assess → Results (score + diagnosis) → Pass threshold. Feedback arrow loops back to the agent.
Chang et al. (2024); Belfrage et al. (2024)
The evaluation
Component 1

① Benchmark — the exam paper

A benchmark is a known set of correct answers. Here, it is a record of how real people actually behaved under a comparable past policy — built from real data, not assumption.

So the fare rise becomes the exam question: run the agents on it, and each agent gives its decision. The benchmark then asks — does what they decided match what people really did?

Question
Bus fare rises 10%. What do you do?
agents decide ↓
Correct answer
Real ridership records from the last fare change.
Chang et al. (2024); Park et al. (2024)
The evaluation
Component 2

② Rubric — the marking scheme

The benchmark says whether the number matches. The rubric says whether each agent's decision is realistic — a set of criteria set by domain experts for what a real person's response looks like here.

A decision earns marks only if it fits the person behind the agent — not just a plausible-sounding answer.

Does the decision fit the person?
✓
Matches the person's personality — lazy, afraid of driving, still rides.
✓
Matches their experience — owns a bike, so switches to it.
✗
Plausible, but wrong person — a car owner who'd never take the bus.
Belfrage et al. (2024)
The evaluation
Component 3

③ Mechanism — find the wrong agent, fix it

Once a decision fails the rubric, the mechanism feeds the result back and corrects the simulation. It combines two layers:

Automated checks — an LLM flags obvious errors quickly, at scale.

Human expert review — for cases that need judgement, domain experts step in.

This is not "AI marking its own homework": the benchmark (real data) sets the standard, and the rubric is set by human experts — the LLM only screens, it does not grade itself.

AUTO
LLM flags obvious errors — fast, at scale.
HUMAN
Experts judge the hard cases.
↓ feed both back
fix the wrong agent → run again, closer each round.
Li, Das & Shirado (2025); Belfrage et al. (2024)
Conclusion
Explore ≠ predict

AI-based policy simulation can explore how people might respond to a policy, but it can't yet predict what will actually happen. To get closer to prediction, the individual-decision step has to be checked against real data and improved where it falls short.

Validation needs past data — and for a genuinely new policy, there isn't any. But validating on cases where data does exist, like a fare rise, tells us how reliably the agents model a decision, and that proven reliability carries over. The deeper limit: the system only checks the decision step, not the whole chain. And any model used in policy must state openly what it assumes and how it was validated — so others can check whether its conclusions hold up, rather than taking them on trust.
